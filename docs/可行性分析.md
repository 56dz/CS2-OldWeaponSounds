# 用 CounterStrikeSharp 编写 CS2 服务端插件，将武器音效（如 AK47）替换为 CS:GO 旧版 —— 可行性分析

> **调研说明**：本文所有技术结论均来自一手源码/官方文件/官方 proto 的实测查证；凡"未查证到"处均已明确标注，请勿在其上做推断。关键来源在文末附录列出。

---

## 一、结论先行

**总体可行，但"纯 CounterStrikeSharp 服务端插件"无法独立完成替换，必须配合内容分发（Workshop addon）。**

| 目标 | 能否达成 | 纯 CSS 插件独立完成 | 必需的配合条件 |
|------|---------|---------------------|----------------|
| 静音/让某些玩家听不到开火音 | ✅ 能 | ✅ 是 | 无 |
| 把 AK47 开火音改成**另一把已有 CS2 武器**的音效 | ✅ 能 | ✅ 是 | 无（仅改 UserMessage 字段） |
| 改开火音的**音量/音调** | ✅ 能 | ✅ 是 | 无（改 packed_params） |
| 替换为 **CS:GO 旧版真实音色** | ✅ 能 | ❌ **否** | 必须 Workshop addon（含旧音 `.vsnd` + 覆盖的 soundevent），由 [MultiAddonManager](https://github.com/Source2ZE/MultiAddonManager) 推给客户端 |
| 只对部分玩家生效（按人开关） | ✅ 能 | ✅ 是 | 无（`RecipientFilter` 按 slot 位掩码） |

**推荐架构（唯一可靠路径）**：
```
CS2 Workshop Addon（内含 soundevents/soundevents_addon.vsndevts 覆盖 Weapon_AK47.Single）
        ↓ 挂载 + 分发
MultiAddonManager（Metamod 插件，强制客户端下载 addon）
        ↓
CounterStrikeSharp 插件（可选，负责 per-player 开关 / 音量音调 / 非预测路径兜底）
```

> ⚠️ **重要否定结论**：CS2 **已不存在** `sv_downloadurl` / `sv_allowdownload` convar（一手证据见 §3.1）。因此 CS:GO/CS:S 时代"配个 FastDL 地址就能下发音效"的做法**在 CS2 不成立**。市面上部分主机商教程（FREAKHOSTING 等）仍教 `sv_downloadurl`，与官方 convar dump 矛盾，且中文社区实测[帖子](https://bbs.csgocn.net/thread-1044.htm)反馈"配好不触发下载"。

> ⚠️ **风险信号（GitHub 实测）**：搜索 "cs2 custom weapon sounds" / "cs2 sound replacer"，**公开仓库 total_count = 0**。**未查证到任何"替换（而非静音/叠加）CS2 武器开火音效"的公开插件**。现有音效插件分两类：
> - **静音类**：[StopSound](https://github.com/oylsister/StopSound) / [CS2-StopSound](https://github.com/darkerz7/CS2-StopSound) / [CS2-MuteSounds](https://github.com/btnrv/CS2-MuteSounds) —— 都走 `HookUserMessage(452)` 收窄 `Recipients`
> - **叠加类**：[cs2-quake-sounds](https://github.com/Kandru/cs2-quake-sounds) / [EndRoundSounds](https://github.com/GianniKoch/EndRoundSounds) / [RoundEndSound](https://github.com/webpashtet/RoundEndSound) —— 走 `EmitSound` 播**新增**音效
>
> **"替换开火音色"这个中间地带没有公开先例**，说明这条路要么没人做、要么有技术坎（很可能是"客户端预测音拦不住"+"音色定义在客户端"两个约束叠加）。本报告给出的 addon 覆盖路线在原理上成立（VDC 明确 addon 可覆盖原版 soundevent），但**无开源先例可直接抄**，需自行验证。

## 二、CS2 音效链路：服务端插件能介入的节点

### 2.1 音效定义（已确证，原始文件级）

- 武器音效定义文件：**`game/csgo/pak01_dir/soundevents/game_sounds_weapons.vsndevts`**（912,247 字节）
  - 注意：**不是** `soundevents_weapons.vsndevts`；基名是 `game_sounds_*`
  - 同级还有 `game_sounds_player/_ui/_physics/_footsteps/_world/_diagnostics/_stopsoundevents.vsndevts`
- **AK47 开火音 soundevent 名 = `Weapon_AK47.Single`**（真实名称，非猜测），真实定义节选：
  ```
  Weapon_AK47.Single =
  {
      type = "csgo_mega"
      volume = 1.100000
      mixgroup = "Weapons"
      enable_child_events = true
      position_offset = [ 0.0, 0.0, 60.0, ]
      broadcast_distance_override = 9000.000000
      vsnd_files_track_01 =
      [
          "sounds/weapons/ak47/ak47_02.vsnd",
          "sounds/weapons/ak47/ak47_01.vsnd",
          "sounds/weapons/ak47/ak47_04.vsnd",
      ]
      soundevent_01 = "Weapon_AK47.SingleDistant"
      metadata = [ "meta", "rifle", ]
  }
  ```
- AK47 同族音效（真实名）：`Weapon_AK47.SingleDistant` / `.Draw` / `.BoltPull` / `.Clipin` / `.Clipout` / `.AddAmmo` / `.WeaponMove1~3` / `.Inspect_*`
- 字段否定结论（对 628 个条目实测 grep=0）：
  - **`soundlevel` 不存在**（`SNDLVL_*` 是 Source 1 soundscript 概念，**不适用 CS2**）
  - **`wave` 不存在**（用 `vsnd_files_track_01 = [ ... ]` 数组）
  - 随机化用显式 `volume_random_min/max`、`pitch_random_min/max`，非 Source 1 的 `0.45,0.65` 写法
- 音效 `type` 枚举：`csgo_mega`（多数武器/音效）、`csgo_music`（受 `snd_musicvolume`）、`csgo_3d`（环境音）

### 2.2 运行期传输机制（一手 protobuf 证据）

soundevent 经 netmessage **由服务端下发**，但**只发哈希 + 参数，不发定义本身**：
```
Protobufs/gameevents.proto:
enum EBaseGameEvents {
    GE_SosStartSoundEvent   = 208;
    GE_SosStopSoundEvent    = 209;
    GE_SosSetSoundEventParams = 210;
    ...
}
message CMsgSosStartSoundEvent {
    optional int32  soundevent_guid  = 1;
    optional fixed32 soundevent_hash = 2;   // 名称哈希（MurmurHash2, seed 0x53524332）
    optional int32  source_entity_index = 3;
    optional int32  seed = 4;
    optional bytes  packed_params    = 5;   // 运行期参数覆盖（音量/音调/位置）
    optional float  start_time = 6;
}
```
**推论**：客户端收到 hash 后，用**本地定义**（客户端 VPK 内的 `game_sounds_weapons.vsndevts_c` 或已挂载 addon 的 soundevents）解析到具体 `.vsnd`。因此：
- 服务端**改不了**客户端解析出的音色，除非客户端本地有覆盖定义
- 服务端**能改** `packed_params`（音量/音调）和 `soundevent_hash`（指向另一个客户端已有的 soundevent）

### 2.3 服务端插件可介入的四个节点

| 节点 | 机制 | CSS 是否可用 | 能否改音色 |
|------|------|-------------|-----------|
| ① 开火广播 UserMessage **452** | `HookUserMessage(452, ...)` | ✅ 可用（3 个公开插件实证） | ❌ 只能改 weapon_id/item_def_index/sound_type → 换成**别的已有武器**音效，或收窄 `Recipients` 静音 |
| ② soundevent 启动 netmessage **208** | `HookUserMessage(208, ...)` | ✅ 可用（CS2-MuteSounds 实证） | ❌ 可读改 `soundevent_hash`/`packed_params`，但音色仍由客户端定义决定 |
| ③ packed_params 参数（本地函数） | `CSoundOpGameSystem::SetSoundEventParam` signature hook | ✅ 可用（EmitSoundVolumeFix 实证） | ❌ 仅音量/音调，非音色 |
| ④ `CBaseEntity.EmitSound` | CSS 官方托管 API | ✅ 可用 | ✅ 可播 addon 里**新定义**的 soundevent |

> **节点 ④ 是唯一能让服务端"指定音色"的入口**，但前提是客户端已挂载包含该 soundevent 定义的 addon。

**UserMessage id 交叉核对（重要）**：
- `208` = **`CMsgSosStartSoundEvent`** ✅ 已确证（Swiftly 生成代码 `MessageId => 208`，字段 `SoundeventGuid/SoundeventHash/SourceEntityIndex/Seed/PackedParams/StartTime`，与 [CS2-MuteSounds](https://github.com/btnrv/CS2-MuteSounds) 读的字段完全一致）
- `210` = `CMsgSosSetSoundEventParams`（QuakeSounds 用它发 `soundevent_guid` + `packed_params` 改音量）
- `452` = **权威消息名未查证到**。CSS/Swiftly 生成枚举均给 `CS_UM_WeaponSound = 369`，与 452 **对不上**；但 3 个公开插件都硬编码 452 且字段语义吻合 `WeaponSound_t`（CSS 枚举 `WEAPON_SOUND_SPECIAL1 = 0x9`，正好对应插件里的 `sound_type = 9`）。→ 结论：**452 是当前游戏构建的武器开火音效 usermessage，确切消息名未查证到**。

## 三、内容分发：旧版 CS:GO 音效如何到达客户端

### 3.1 FastDL / `sv_downloadurl` 在 CS2 不可用（一手证据）

对 CS2 完整 convar dump（12,992 行）与 command dump（3,905 行）grep：
- `sv_downloadurl` → **0 命中**
- `sv_allowdownload` → **0 命中**
- `sv_allowupload` → **0 命中**
- `sv_pure` → **0 命中**（但引擎内部仍有 pure 校验错误路径 `error_message_explain_pure`）

**结论倾向**：CS2 传统 FastDL 任意文件 HTTP 下载**未被 Valve 支持**。社区/主机商口径矛盾，建议**不要依赖 FastDL**。

### 3.2 Workshop addon 是唯一可靠分发路径（已确证）

**官方 addon 覆盖机制**（Valve VDC，via archive.org）：
- 自定义/覆盖 soundevent **只从 addon 的 `soundevents/soundevents_addon.vsndevts` 文件 precache**
- 原文：*"To override existing soundevents, that is all that is required."* —— 在该文件里**重定义同名 soundevent** 即可覆盖原版
- 原文：*"the map must be loaded within a mounted addon … standalone .vpks launched with the `map` console command in an insecure CS2 instance will not automatically precache soundevents."*
- 校验：控制台 `snd_list_soundevents`

**因此覆盖 AK47 = 在 addon 的 `soundevents_addon.vsndevts` 里重写 `Weapon_AK47.Single`**，指向旧版 CS:GO 的 `.vsnd`。

### 3.3 分发组件：MultiAddonManager（一手 README）

MetaMod:Source 插件，负责让客户端下载并挂载多个 workshop addon：
- `mm_extra_addons <ids>` — 挂载并让客户端下载；下载完自动 reload 地图以便 precache
- `mm_client_extra_addons <ids>` — 仅客户端 addon（服务端不加载）
- `mm_extra_addons_timeout <秒>(默认10)` — 超时客户端**自动重连**完成下载
- `mm_addon_mount_download <0/1>` — 强制重新下载以应用更新
- `mm_cache_clients_with_addons` / `mm_cache_clients_duration` — 按 SteamID 缓存避免重发
- `mm_block_disconnect_messages <0/1>` — 屏蔽下载重连产生的 "loop shutdown" 刷屏
- 公开接口 `public/imultiaddonmanager.h`（`MetaFactory` 查询）

**用户体验代价**：进服会因下载 addon 被超时打断并重连（这正是上述超时/屏蔽命令存在的原因）；下载走 Steam Workshop 侧而非游戏服 HTTP。

### 3.4 分发路径对比

| 路径 | CS2 是否可用 | 分发成本 | 覆盖范围 | 复杂度 | 可靠性 |
|------|-------------|---------|---------|--------|--------|
| **A. Workshop addon + MultiAddonManager** | ✅ 可用（一手确证） | 中（需制作+发布 workshop 物品） | 全局 | 中 | **高** |
| B. 传统 FastDL `sv_downloadurl` | ❌ convar 不存在 | — | — | — | **不可用** |
| C. 客户端手动安装 mod | ✅ 可用 | 低 | 仅装了的人 | 低 | 低（漏装则听不到） |
| D. CSS 改 soundevent_hash 换成已有音效 | ✅ 可用 | 零 | 全局 | 高（需逆向） | 中（仅限游戏内已有音色） |

**推荐 A**（+ 可选 D 做"零分发的近似替代"，如把 AK47 换成 CS2 里另一把枪的音效）。

### 3.5 音源获取：CS:GO 旧版音频从哪来（新增）

旧版音效的**前置条件**是先拿到 CS:GO 的音频文件。经查证有三条可用路径：

**路径①：安装 CS:GO 独立版（客户端，推荐用于提取）**
- Valve 于 **2026 年 3 月**把 CS:GO 作为**独立 App 重新上架**：app **4465480**（SubID 1558686）
- **免费下载安装**，但**仅能离线对战**（无匹配/官方服务器）—— 对"导文件"这一用途**没有影响**
- 来源：[ithome 报道](https://www.ithome.com/0/925/792.htm)、[Fragster 安装指南](https://www.fragster.com/csgo-on-steam-in-2026-how-to-install-the-legacy-build-and-why-comeback-talk-is-trending-again/)

**路径②：CS2 内置 `csgo_legacy` 分支（无需另装 App）**
1. Steam → 库 → 右键 **Counter-Strike 2** → 属性
2. **Betas** 标签 → Beta Participation 选 **`csgo_legacy`**
3. Steam 会下载 legacy 文件

**路径③：SteamCMD 下载 CS:GO 专用服务器（服务端，免登录/免拥有）** ★服务端管理员首选
- 中文社区实证（2026-03-04，多人回复"成功了"）：`login anonymous` + `app_update 740 validate` 仍可下载 CS:GO DS 内容
- 开服时还需把 `csgo/steam.inf` 的 `appID` 改为 `4465480`，并申请 4465480 的 GSLT
- 来源：[csgocn 开服帖](https://bbs.csgocn.net/thread-1138.htm)、[SteamDB app 740 关联应用](https://steamdb.info/app/740/linked/)
- ⚠️ **需本地验证**：app 740 的 `pak01_*.vpk` 是否包含完整武器 `.wav`（服务端理论上含共享资源，但**未查证到明文**）。验证方法：装完后用 VPK 工具打开 `csgo/pak01_dir.vpk`，查找 `sound/weapons/ak47/` 目录

**音频提取工具**（CS:GO 是 Source 1 VPK，内部为 `.wav`）：
- **GCFScape** —— 经典 Source 1 VPK 提取工具
- **VPK.exe** —— Valve 自带
- **Source2Viewer / ValveResourceFormat** —— 亦支持部分 Source 1 格式
- 关注路径：`csgo/pak01_dir.vpk` → `sound/weapons/ak47/ak47-*.wav`

### 3.6 ⚠️ 关键坑：CS:GO 是 `.wav`，CS2 要 `.vsnd`（必须转换）

**这一步不能省** —— 把 CS:GO 的 `.wav` 直接丢进 CS2 addon **不会生效**：
- CS:GO（Source 1）：音频为 **`.wav`**（16-bit PCM），由 `scripts/game_sounds_weapons.txt` 以 `"wave"` / `"rndwave"` 引用
- CS2（Source 2）：音频必须编译为 **`.vsnd`**，由 `soundevents/*.vsndevts` 以 `vsnd_files_track_01 = [ "sounds/...vsnd" ]` 引用

**转换路径**：
- **官方路线（推荐）**：装 **CS2 Workshop Tools**，把 `.wav` 放进 addon 的 `sounds/` 目录，工具链会**自动编译**为 `.vsnd`（VDC：*"Compile all of these files (should be done automatically)"*；若编译失败通常是 `vsndevts` 语法错误）
- **社区工具**：存在 `quad-damage/cs2_sound_converter`（Lua，2025-04）等转换器，另有 Wallworm "Sound Compiler" 等；⚠️ **这些工具的具体工作流未查证到**，使用前请自行验证

**✅ 好消息：soundevent 名与 CS:GO 同名**
CS:GO 的 `Weapon_AK47.Single` 与 CS2 的 `Weapon_AK47.Single` **名称一致**（命名约定被 CS2 继承）。因此 addon 覆盖时**不需要改名**，直接在 `soundevents_addon.vsndevts` 里重定义同名事件即可 —— 这正是 §3.2 所说的"*To override existing soundevents, that is all that is required.*"

**完整链路小结**：
```
安装 CS:GO 独立版(4465480) / csgo_legacy 分支 / SteamCMD app 740
      ↓ 用 GCFScape 从 csgo/pak01_dir.vpk 提取
sound/weapons/ak47/ak47-*.wav   （Source 1 格式）
      ↓ 放入 CS2 addon 的 sounds/ 目录，Workshop Tools 自动编译
sounds/weapons/ak47/ak47_*.vsnd （Source 2 格式）
      ↓ 在 soundevents/soundevents_addon.vsndevts 里重定义
Weapon_AK47.Single → 指向上述 .vsnd
      ↓ 发布 Workshop 物品 + MultiAddonManager 分发
客户端听到 CS:GO 旧版枪声
```

**合规提醒**（同 §6 风险表）：CS:GO 音效资产版权归 Valve；在 Valve 自家游戏之间搬运、仅用于社区服通常被视为灰色地带（现有大量 CS:GO 音效 mod 如此操作），但**公开再分发**仍有 DMCA 风险。**未查证到 Valve 的明确表态或官方许可**。

## 四、CounterStrikeSharp 插件工程要点

### 4.1 工程结构

```xml
<!-- OldCSGOSounds.csproj -->
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
    <AllowUnsafeBlocks>true</AllowUnsafeBlocks>
    <GenerateAssemblyInfo>false</GenerateAssemblyInfo>
    <CopyLocalLockFileAssemblies>false</CopyLocalLockFileAssemblies>
  </PropertyGroup>
  <ItemGroup>
    <!-- 最新正式版 1.0.376（NuGet 共 342 版，另有 2.0.0-alpha.1） -->
    <PackageReference Include="CounterStrikeSharp.API" Version="1.0.376" />
  </ItemGroup>
</Project>
```

**目标框架的真实情况** ⚠️：
- 官方文档要求 **.NET 8.0 SDK**，csproj 写 `<TargetFramework>net8.0</TargetFramework>`
- **但仓库 main 的自身工程与示例已是 `net10.0`**，`CounterStrikeSharp.API.csproj` 带 `<RollForward>Major</RollForward>`（注释："Major roll-forward lets net8.0-targeted plugin assemblies resolve and load on the bundled .NET 10 runtime"）
- 结论：**新插件建议写 `net8.0`（最稳妥兼容），依赖 CSS 自带的 .NET 10 runtime 回滚加载**；社区插件（如 QuakeSounds）已直接写 `net10.0`

- 部署路径：`game/csgo/addons/counterstrikesharp/plugins/<与 dll 同名文件夹>/`，放 `<Name>.dll` + `<Name>.deps.json` + `<Name>.pdb`（第三方 dll 也要拷进去）
- 配置路径：`addons/counterstrikesharp/configs/plugins/<Plugin>/<Plugin>.json`
- 前置依赖：**Metamod:Source 2.X Dev Build build 1467+（需 KHook 支持）** + **CounterStrikeSharp 本体**（+ 若要分发音效，另需 MultiAddonManager）
  - `gameinfo.gi` 的 `Game_LowViolence csgo_lv` 下加 `Game csgo/addons/metamod`
  - 首次安装须下 **with-runtime** 版（自带 .NET runtime）；Windows 需 VC++ Redist；Linux 可能需 libicu
- 入口类：`public class X : BasePlugin`，**必须** override `ModuleName`、`ModuleVersion`；可 override `ModuleAuthor`、`ModuleDescription`、`Load(bool)`、`Unload(bool)`
  - ⚠️ **没有 `[PluginAuthor]` 属性**（docfx 索引 0 命中）—— 插件元数据**只能**用 `Module*` 属性
  - 常用：`[MinimumApiVersion(80)]`、`[ConsoleCommand("css_x")]` + `[CommandHelper(...)]`
- 热重载：替换 dll 即自动 Unload/Load

### 4.2 CSS 关键 API（源码级已核对）

**① 音效播放 —— `CBaseEntity.EmitSound`**（`managed/CounterStrikeSharp.API/Core/Model/CBaseEntity.cs` L94–113，**不在** `CEntityInstance` 上）：
```csharp
/// <summary>Emit a soundevent to all players.</summary>
/// <returns>The sound event guid.</returns>
public uint EmitSound(string soundEventName, RecipientFilter? recipients = null,
                      float volume = 1f, float pitch = 0)
{
    Guard.IsValidEntity(this);
    if (recipients == null) { recipients = new RecipientFilter(); recipients.AddAllPlayers(); }
    return NativeAPI.EmitSoundFilter(recipients.GetRecipientMask(), this.Index, soundEventName, volume, pitch);
}
```
- 底层 native：`NativeAPI.EmitSoundFilter(ulong filtermask, uint ent, string sound, float volume, float pitch) : uint`
- **无 delay 参数**；支持按玩家 `RecipientFilter`、`volume`、`pitch`
- ⚠️ **`pitch` 实际无效** —— CSS C++ 源码注释原文（`src/core/managers/entity_manager.cpp`）：`params.m_nPitch = flPitch; // not working, can't fix, i think the game abandon it`
- `EmitSoundParams` / `SoundEvent`（CSS 类型）/ `CSoundOpGameSystem` / `SoundHook` 在 CSS API 中**不存在**（docfx 全站索引 0 命中）；`SoundEvent` 命中的只是 schema 实体类（`CSoundEventEntity` 等），**不是播放 API**

**①-b 引擎真名与签名（关键，可签名 hook）**：
- C++ 引擎函数真名：**`CBaseEntity::EmitSoundFilter(CRecipientFilter&, CEntityIndex, const EmitSound_t&)`**，返回 `SndOpEventGuid_t`（24 字节结构）
- **CSS 官方 gamedata 里就有这个签名**（`configs/addons/counterstrikesharp/gamedata/gamedata.json` L155）：
  ```json
  "CBaseEntity_EmitSoundFilter": {
    "signatures": {
      "library": "server",
      "windows": "40 53 48 83 EC ? 4C 89 4C 24 ? 48 8B D9 45 8B C8",
      "linux": "55 48 89 E5 53 48 89 FB 48 83 EC ? E8 ? ? ? ? 48 89 D8 48 8B 5D ? C9 C3 ..."
    }
  }
  ```
- 托管侧 `GameData.GetSignature(string)` 是公开 API，`MemoryFunctionVoid/WithReturn` 支持 `.Hook()` → **"按签名挂钩引擎发声函数"在机制上可用 CSS 自身 API 表达**
- ⚠️ **但** `CRecipientFilter` / `CEntityIndex` / `EmitSound_t` / `SndOpEventGuid_t` **都未导出到托管层**，只能退化为 `IntPtr` + `DynamicHook.GetParam/SetParam`，且返回 24 字节结构体。**未查证到任何公开插件真的这么做过** —— 属"机制可行、无先例、高风险"。

**①-c `EmitSound_t`（C++ 结构，未导出）** —— 含 `m_flSoundTime`（延迟）、`m_vecOrigin`、`m_nFlags`（定位方式）等托管 API **没有暴露**的字段。

**② 按玩家分发 —— `RecipientFilter`**（`CounterStrikeSharp.API.Modules.Utils`）：
```csharp
public class RecipientFilter : IList<CCSPlayerController>, IMarshalToNative {
    public RecipientFilter();
    public RecipientFilter(params CCSPlayerController[] slots);
    public RecipientFilter(params int[] slots);
    public RecipientFilter(ulong mask);        // bit i = player slot i（64 位掩码，按 slot 非 userid）
    public ulong GetRecipientMask();
    public void Add(int slot); public void Add(CCSPlayerController item);
    public void AddAllPlayers(); public void Clear();
    public static implicit operator RecipientFilter(CCSPlayerController player);
}
```

**③ 无官方 SoundHook** ⚠️：
- CSS **不提供**类似 SourceMod `SoundHook` 的托管 API
- 替换/拦截原版音只能用通用内存 hook：`VirtualFunctionVoid<T...>` / `VirtualFunctionWithReturn<...>` + `.Hook(cb, HookMode.Pre)`
- 回调 `HookResult cb(DynamicHook hook)`，`DynamicHook` 提供 `GetParam<T>(int)` / `SetParam<T>(int,T)` / `GetReturn<T>()` / `SetReturn<T>(T)`
- 支持 `GameData.GetSignature(...)`（签名）或 `GameData.GetOffset(...)`（vtable 偏移）
- `HookResult { Continue=0, Changed=1, Handled=3, Stop=4 }`，`Handled`/`Stop` 表示"原方法不被调用"
- ⚠️ **hook 哪个符号需自行逆向**，CSS 不提供现成清单

**④ 相关 GameEvent**（已确认存在）：

| 事件名 | 生成类 | 字段 |
|--------|--------|------|
| `weapon_fire` | `EventWeaponFire` | `bool Silenced`、`CCSPlayerController? Userid`、`string Weapon` |
| `player_shoot` | `EventPlayerShoot` | `int Mode`、`CCSPlayerController? Userid`、`int Weapon` |
| — | `EventPlayerSound`、`EventBulletImpact` | （另有，未细读） |

注册：`[GameEventHandler(HookMode.Pre)] public HookResult OnX(EventX e, GameEventInfo info)` 或 `RegisterEventHandler<T>(handler, mode)`；`GameEventInfo.DontBroadcast`（`ref bool`）可阻止默认广播。

### 4.3 插件骨架（基于已实证的 StopSound 模式）

已实证的 [StopSound](https://github.com/oylsister/StopSound) 插件（源码逐行核对）核心逻辑：
```csharp
public HookResult Hook_WeaponFiring(UserMessage userMessage)
{
    var weaponid     = userMessage.ReadUInt("weapon_id");
    var soundType    = userMessage.ReadInt ("sound_type");
    var itemdefindex = userMessage.ReadUInt("item_def_index");

    userMessage.SetUInt("weapon_id", 0);
    userMessage.SetInt ("sound_type", 9);         // 9 = 消音音效
    userMessage.SetUInt("item_def_index", 61);    // 61 用于消音
    userMessage.Recipients = GetRecipientFromMode(SoundMode.M_SILENCER); // 只发给特定玩家
    userMessage.Send();

    userMessage.SetUInt("weapon_id", weaponid);
    userMessage.SetInt ("sound_type", soundType);
    userMessage.SetUInt("item_def_index", itemdefindex);
    userMessage.Recipients = GetRecipientFromMode(SoundMode.M_NORMAL);
    return HookResult.Continue;
}
// Load(): HookUserMessage(452, Hook_WeaponFiring, HookMode.Pre);
```
**结论**：服务端可完全控制"发给谁、用哪个 weapon_id/item_def_index/sound_type"，且可按玩家分组（StopSound 正是把开火音改成消音音效并按人分发）。

**骨架示意（本项目）**：
```csharp
using CounterStrikeSharp.API;
using CounterStrikeSharp.API.Core;
using CounterStrikeSharp.API.Core.Attributes.Registration;
using CounterStrikeSharp.API.Modules.UserMessages;
using CounterStrikeSharp.API.Modules.Utils;

namespace OldCSGOSounds;

public class OldCSGOSoundsPlugin : BasePlugin
{
    public override string ModuleName   => "OldCSGO Sounds";
    public override string ModuleVersion => "1.0.0";
    public override string ModuleAuthor  => "YourName";

    // 玩家级开关（可存 SQLite，参考 StopSound）
    private readonly Dictionary<CCSPlayerController, bool> _enabled = new();

    public override void Load(bool hotReload)
    {
        // 仅当"纯改已有武器音色/静音"时需要；替换为 CS:GO 旧音主要靠 addon 覆盖
        HookUserMessage(452, OnWeaponFiring, HookMode.Pre);
        RegisterEventHandler<EventWeaponFire>(OnWeaponFire, HookMode.Post);
        RegisterListener<OnClientPutInServer>(OnClientPutInServer);
    }

    private HookResult OnWeaponFiring(UserMessage userMessage)
    {
        // 方案 D（零分发）：把 AK47 换成另一把已有武器的音色
        var itemId = userMessage.ReadUInt("item_def_index");
        // if (itemId == 7 /* AK47 */) userMessage.SetUInt("item_def_index", /* 目标武器 */);
        return HookResult.Continue;
    }

    private HookResult OnWeaponFire(EventWeaponFire e, GameEventInfo info)
    {
        // 方案 A（推荐，需 addon 已挂载）：对开火者本人兜底播放 addon 中覆盖后的 soundevent。
        // 注意：客户端预测音服务端拦不住，若这里再 EmitSound 可能双重音，需实测权衡。
        // var weapon = e.Userid?.PlayerPawn.Value?.WeaponServices?.MyActiveWeapon.Value;
        // var rf = new RecipientFilter(); rf.Add(e.Userid!);
        // weapon?.EmitSound("Weapon_AK47.Single", rf, volume: 1.0f);
        return HookResult.Continue;
    }

    private void OnClientPutInServer(int slot)
    {
        var p = Utilities.GetPlayerFromSlot(slot);
        if (p is { IsBot: false }) _enabled[p] = true;
    }
}
```

> ⚠️ **骨架为示意**：`item_def_index` 的映射值、以及"客户端预测音是否与服务端广播音双重"这两点均需实测（见 §6 风险）。

**另一条已实证的参数修改路径（usermessage 210）** —— 来自 [cs2-quake-sounds](https://github.com/Kandru/cs2-quake-sounds) `src/utils/SoundEvents.cs`，**不是 CSS API，是插件自拼 protobuf 字节**：
```csharp
// 自己算 soundevent 名 hash（MurmurHash2, seed 0x53524332，名字先小写化）
// 字段名 hash seed 0xB5D9F700（注：与音量修复插件的 0x31415926 不同，两套用途）
UserMessage message = UserMessage.FromId(210);        // CMsgSosSetSoundEventParams
message.SetUInt("soundevent_guid", guid);
message.SetBytes("packed_params", BuildPackedParams()); // 如 ("volume", fieldType=4, float bytes)
if (recipients != null) message.Recipients = recipients;
message.Send();
```
> 这解释了 §2.3 节点③的另一种实现：不 signature hook，直接发 usermessage 210 改 `packed_params`。**社区已有两套 hash seed 用法，需按目标字段实测**。

### 4.4 可选：Signature Hook 改 packed_params（音量/音调）

已有实证 [EmitSoundVolumeFix](https://github.com/samyycX/CS2-EmitSoundVolumeFix)：
```csharp
using CounterStrikeSharp.API.Modules.Memory.DynamicFunctions;

public MemoryFunctionWithReturn<nint,nint,nint,uint,nint,uint,uint,byte> _setParam =
    new(GameData.GetSignature("CSoundOpGameSystem_SetSoundEventParam_2"));

public override void Load(bool hotReload) => _setParam.Hook(OnSetParam, HookMode.Pre);

public HookResult OnSetParam(DynamicHook hook)
{
    var paramHash = hook.GetParam<uint>(/* 2 或 3，Windows/Linux 不同 */);
    // 如 0xBD6054E9 = public.volume
    return HookResult.Continue;
}
```
签名 JSON 放 `addons/counterstrikesharp/gamedata/<插件名>.json`；**每次 CS2 更新后需重新定位**。

### 4.5 CSS vs Swiftly（横向对照）

| 能力 | CounterStrikeSharp | Swiftly |
|------|-------------------|---------|
| 播放音效 | `CBaseEntity.EmitSound(name, filter, volume, pitch)`（pitch 无效） | `SoundEvent` 类（`Name/Volume/Pitch/Recipients/Emit()`，pitch 走 `public.pitch` 参数，**可能有效**） |
| 按玩家分发 | `RecipientFilter`（64 位 slot 掩码） | `CRecipientFilter` |
| 音效拦截 hook | ❌ 无（只有通用 MemoryFunction/VirtualFunction + UserMessage hook） | ❌ **无**（GameHooks 全清单 + natives 中无 EmitSound/声音拦截） |
| 改 soundevent 参数 | UserMessage 210 / signature hook | `SoundEvent.SetFloat("public.volume", ...)` 封装更好 |
| 定位发声 | `EmitSound_t` 的 origin/flags **未导出** | `SourceEntityIndex`（-1=本地 / 0=世界 / 其他=实体）、`SetFloat3("public.position",...)` |

> **对照结论**：两个框架都**没有官方音效拦截 hook**，"替换原版开火音"在两边都得靠 `HookUserMessage(452)`（CSS）或等价手段。Swiftly 的 `SoundEvent` 类在参数封装上更友好，但本项目目标是 CSS，故以 CSS 为准。
