## 2. 方案架构

### 2.1 为什么必须用 addon（这是整个项目的核心结论）

CS2 服务端下发枪声时**只发送 soundevent 的名字哈希 + packed_params**（网络消息 `CMsgSosStartSoundEvent` = 208），
**音色由客户端本地解析**。因此服务端插件无论怎么做都**改不了音色**，唯一可行的路径是
**做一个 addon 覆盖同名 soundevent，让客户端自己去播旧音频**。插件只能做"开关"（拦消息 / 重放别的消息）。

### 2.2 两层结构

```
【一层】addon：soundevents/soundevents_addon.vsndevts
        把 Weapon_XXX.Single 的 vsnd_files_track_01 换成 CS:GO 旧音频 → 默认全场都是旧音
        ↑ 客户端解析，保留 3D 定位 / 遮挡 / 衰减（因为只换了音频文件，没换事件参数）

【二层】CSS 插件 OldWeaponSounds
        默认什么都不做（= 听 addon 的旧音）
        某武器 enabled=false 时：拦下 452 消息 → 先播 Orig_Weapon_XXX.Single（内容=CS2 原事件）
        → 只有 EmitSound 返回 guid≠0 才返回 HookResult.Handled 屏蔽原版 → 该武器还原 CS2 原声
```

**为什么不能直接 `EmitSound` 一个裸 `.vsnd` 路径**：社区实测那样会丢失 3D 定位（变成无衰减的全局音）。
所以必须走"覆盖 soundevent"这条路。

### 2.3 为什么每把枪有两个事件

| 事件 | 内容 | 用途 |
|---|---|---|
| `Weapon_XXX.Single` | CS:GO 旧音频 | addon 覆盖后的默认结果 |
| `Orig_Weapon_XXX.Single` | 与 CS2 原事件**逐字段相同**（只改事件名） | 插件"还原成 CS2 原声"时重放 |

### 2.4 防无声保证（重要设计）

定位不到开枪者 / pawn 无效 / `EmitSound` 返回 `guid=0` / 任何异常 —— 一律返回 `HookResult.Continue`
**保留原版音效**，日志写 `[保留原版]`。宁可没换成，也绝不出现"无声枪"。

## 4. addon 生成链路

### 4.1 输入素材

1. **`gsw.txt`** —— CS2 真实 soundevent 定义（纯文本 kv3）。
   CS2 游戏里只有**编译后**的 `game_sounds_weapons.vsndevts_c`，`resourceinfo.exe` 也导不出文本
   （DATA 块是 old-introspected blob，报 `ConvertOldIntrospectedResourceDataToKV3 - No introspection dictionary!`），
   需从社区转储获取。当前副本在 `data/gsw.txt`（930 KB，gitignored）。
2. **5 个 CS:GO 原始 wav** —— 只在 CS:GO 客户端/DS 里有，CS2 已无原始 wav。

### 4.2 生成

```bash
node tools/build_full_addon.js data/gsw.txt tools/legacy_map_full.json addon/soundevents/soundevents_addon.vsndevts
node tools/verify_full_addon.js addon/soundevents/soundevents_addon.vsndevts data/gsw.txt tools/legacy_map_full.json
```

生成逻辑（`tools/build_full_addon.js`）：
1. 按 `\t<事件名> = ` 切出 `gsw.txt` 里的一级事件块（共数百个）。
2. 对每个武器：取 `Weapon_XXX.Single` 原块，**只替换 `vsnd_files_track_01`**（兼容数组与标量两种写法），其余字段原样 → 旧音块。
3. 原块改名 `Orig_Weapon_XXX.Single`，内容完全不动 → 原音块。
4. 自检：大括号平衡、事件数 = 武器数 × 2、vsnd 字段数正确。

### 4.3 文件格式的坑（必须遵守）

- 文件头必须是 kv3 头注释：
  `<!-- kv3 encoding:text:version{e21c7f3c-8a33-41c5-9977-a76d3a32aa0d} format:generic:version{7412167c-06e9-4698-aff2-e63eb59037e7} -->`
- 根块必须是**匿名** `{ }`。写成 `soundevents_addon = {` 会失效。
- 字段名必须完整（`soundevent` + `location` 等），缺字段的块会被引擎丢弃。

### 4.4 编译（本机 Windows 上做）

```cmd
cd <CS2>\content\csgo_addons\csgo_old_weapon_sounds\soundevents
"<CS2>\game\bin\win64\resourcecompiler.exe" -i soundevents_addon.vsndevts -o . -f -nop4 -game "<CS2>\game\csgo"
```

**坑 1**：`-game` 要传**目录** `...\game\csgo`，传 `gameinfo.gi` 文件路径会报
`FATAL ERROR: Application unable to load gameinfo.gi file from directory "csgo\gameinfo.gi"`。

**坑 2（致命）**：发布用的是 `game\csgo\gameinfo.gi` 里的 `AddonConfig -> VpkDirectories` ——
这是**打包白名单**。默认不含 `weapons` / `characters` / `agents`。仓库提供 `tools/fix-gameinfo-weapons.cmd`
（幂等、去 BOM）修复；**游戏每次更新都会还原 gameinfo.gi，需重跑**。

**坑 3**：Windows `MAX_PATH` 259 —— 创意工坊工具不支持长路径。addon 目录名必须短（如 `wa`）。

编译后校验：
```bash
resourceinfo.exe -i soundevents_addon.vsndevts_c -all -baremode -game "<CS2>\game\csgo" > dump.txt
node tools/verify_compiled_vsndevts.js dump.txt data/gsw.txt tools/legacy_map_full.json
```
预期：70 个事件全在册，`vsndevts_c` ≈ **10,069 字节**。

## 6. 插件实现（`plugin/Plugin.cs`，566 行，v2.0.0）

### 6.1 关键 API

| API | 用途 |
|---|---|
| `HookUserMessage(452, cb, HookMode.Pre)` | 拦截武器开火音效消息（fields: `weapon_id` / `sound_type` / `item_def_index`） |
| `RegisterEventHandler<EventWeaponFire>(OnWeaponFire, HookMode.Pre)` | 记录"谁开了什么枪"，用于给 452 找开枪者 |
| `CBaseEntity.EmitSound(string eventName, RecipientFilter, float volume=1f, float pitch=0) : uint` | 播放事件，返回 guid（0 = 失败）。**pitch 参数是坏的**（CSS 源码注释已说明） |
| `RecipientFilter.AddAllPlayers()` | 接收者过滤 |
| `Utilities.GetEntityFromIndex<T>(int)` / `Utilities.GetPlayers()` | 实体/玩家查询 |

> CSS **没有** SoundHook；也没有 `LoadConfig`（配置读取需自己用 `System.Text.Json` 做）。

### 6.2 452 消息的真相（踩过坑，别重复）

- `weapon_id` **不是实体索引**。AK47 实测恒为 `4276626` → `Utilities.GetEntityFromIndex` 得到无效实体。
- 因此 `ResolveShooter()` 走两级：
  - **A**：把 `weapon_id` 当实体索引 → `OwnerEntity` → 反查控制器；
  - **B**：`weapon_fire` 事件维护的 `(defIndex → player, 时间)` FIFO，取 1 秒内最近一条。
- 线上实际生效的是 **B** 路径。A 理论上更快，但依赖 `weapon_id` 的语义（CSS/Swiftly 的枚举把 369 叫 `CS_UM_WeaponSound`，452 的权威名字未证实）。

### 6.3 配置路径（v2 已改）

```
$C/configs/plugins/OldWeaponSounds/OldWeaponSounds.json
```

`ResolveConfigPath()` 逻辑：
1. 惯例位置有文件 → 直接用；
2. 惯例位置没有、但插件目录下有旧 `config.json` → **自动迁移**并写日志；
3. 都没有（全新安装）→ 在惯例位置生成完整默认配置（35 把，全部 `enabled=true`）。

> 用户问过"为什么 config 不在惯例位置" —— 早期放在插件目录是为了自包含，缺点是升级插件目录会覆盖用户配置，所以 v2 改到惯例位置并做了迁移。
> 迁移已在生产验证：`plugins/OldWeaponSounds/config.json` 已不再被使用（可以删）。

`SaveConfig()` 会写 4 行 `//` 注释头；读配置用 `ReadCommentHandling = JsonCommentHandling.Skip`，所以注释安全。
写文件用**无 BOM** UTF-8（用户反映过带 BOM 会让某些工具报错）。

### 6.4 内建默认武器表

`BuildDefaultWeapons()` 里硬编码 35 条（由 `tools/gen_defaults_cs.js` 从 `config.json` 生成，**勿手工编辑**），
保证"只部署 dll、不带 config"时也能生成完整配置。

### 6.5 换模型插件兼容（`emitForSubclass` / `forceEmitAlways`）

换 subclass 会**连带换掉整套 VData**，其中包括开火音效表 `m_aShootSounds`。
模型包里这张表可能是错的，甚至指向不存在的事件名（实测 AWP 皮肤写成小写 `Weapon_scar20.Single`，
CS2 真实事件是 `Weapon_SCAR20.Single`；事件名按字符串哈希、**区分大小写** → 未定义 → 完全无声）。

所以 `OnWeaponFireSound` 里会读 `ActiveWeapon.SubclassID`：`!= 0` 说明被换过模型，
此时插件**显式播放本武器正确的旧音**，不再信任 VData。

| 配置 | 行为 |
|---|---|
| `emitForSubclass`（默认 `false`） | true = 检测到自定义 subclass 时插件接管 |
| `forceEmitAlways`（默认 `false`） | true = 对所有武器都显式播放（排错用，会掩盖 3D 距离衰减） |

> **现网状态：两者都是 `false`** —— 因为音效包已经和模型包融合成 3819972417，VData 里的事件名已修好，
> 走原版路径最安全（不会因为 `EmitSound` 出问题而屏蔽掉本来能响的声音）。

### 6.6 命令

```

css_oldws list                         列出被还原成 CS2 原声的武器
```

### 7.1 v7 相对 v6 的实质改动

**补上 57 个 `_Q` 安静版工艺音事件**（这是「切枪拉栓声还是 CS2 的」的真正原因）。

CS2 给工艺音配了 `_Q` 变体（`BoltPull_Q` / `BoltBack_Q` / `Slideback_Q` / `Sliderelease_Q` /
`Pump_Q` / `Clipin_Q` …，共 60 个，其中 57 个的主事件在覆盖计划内），volume 通常是主事件的 0.5，
其余字段与主事件只差 `display_broadcast=false` 和 `metadata`。**引擎在「快速动作」场景
（快速切枪、快速换弹）播的是 `_Q` 而不是主事件。**

之前把这些 `_Q` 判为「CS:GO 没有对应事件 → 不处理」，导致主事件已换成 CS:GO 旧音、
但玩家一快速切枪仍然听到 CS2 新录音。`_Q` 不需要 CS:GO 有同名事件 —— 它只是主事件的
音量变体，把主事件的 CS:GO 素材搬过来、按 CS2 原有的 `_Q`/主 音量比缩放即可。

实现：`build_legacy_all.js` 的 3a-2 段（`qEvents` 循环），复用 `replaceVsnd` / `fitVariants` /
`setVolume` / `setDuration`；主覆盖块循环里用 `emittedVolume` 记录最终音量供 `_Q` 继承。

**验证方法（可复用）**：从客户端实际加载的 vpk 里解出自己打包的 vsnd_c，
用 CS:GO 原始 wav 的 PCM 做探针（`tools/` 外的一次性脚本 `.tmp/pcm_probe_ab.js`）：
AK47 的 `draw / clipin / clipout / boltpull` 四个文件都是 **3/3 命中**，
证明素材层面确实是 CS:GO 原始字节，问题只可能在事件路由。

## 8. 踩坑清单（血泪史，按代价排序）

| # | 坑 | 症状 | 解法 |
|---|---|---|---|
| 1 | **两个 addon 都提供 `scripts/weapons.vdata_c`** | 换装插件的皮肤子类全部失效、武器变回原版模型，**但匕首的持握动作已经是新模型的**（动作来自插件，模型来自 VData）；只有死亡重生换新实体才恢复 | 后加载的 addon 赢。要么融合成一个包，要么不要同时挂两个模型/换装类 addon |

## 11. 常用排错流程

**"某把枪还是 CS2 声音"**
1. `css_oldws status` → 看该武器 `enabled` 是否为 true
2. `css_oldws test Weapon_XXX.Single` → `guid=0` 说明事件名/编译有问题
3. 确认 `soundevents_addon.vsndevts_c` 在包里且是**当前版本大小**（v7 = 60,801 B / wa 版 60,785 B）
4. 看客户端是否真下载了包（MM 日志 `mm_addon_debug 1`）
5. **如果是「快速切枪/快速换弹」才听到 CS2 音** → 查 `_Q` 变体有没有覆盖（§7.1）
6. **用 PCM 探针做终审**：从客户端实际加载的 vpk 里解出自己包的 vsnd_c，用 CS:GO 原始
   wav 的 PCM 前 4096 字节做探针 `indexOf`（`.tmp/pcm_probe_ab.js`）。命中 = 素材确实是
   CS:GO 原始字节，问题在事件路由；不命中 = 打包/编译环节被换掉了

**"某把枪完全没声音"**
1. 优先怀疑 VData 的 `m_aShootSounds`（换模型插件）；临时把 `emitForSubclass` 设 `true` 验证
2. 看 `oldweaponsounds.log` 有没有 `[保留原版]`（有 = 插件正确退让，问题在 addon/VData）

**"改了 addon 但客户端没变化"**
1. 服务端缓存目录里的文件是不是新的（`stat` 看时间戳）
2. `mm_addon_mount_download 1` 有没有开
3. 客户端是否清过 `steamapps/workshop/content/730/<ID>`
4. **新版是否还在审核**：`steamcmd +workshop_download_item 730 <ID> +quit` 下载的字节数
   与本地 `vpks/<ID>/` 对比。一样 = 已过审；还是旧尺寸 = 审核中（§8 #21/#23）
5. acf 里的 `manifest` / `latest_manifest` 是否等于实际要用的版本号
